# Функциональные требования LifeIsGame в форме вариантов использования

Модель составлена по главе 9 книги Мартина Фаулера «UML. Основы», 3-е издание. Вариант использования понимается как множество сценариев, объединённых общей целью внешнего актора. Поэтому диаграммы показывают обзор, а основная функциональная конкретика находится в текстовых сценариях.

## Правила моделирования

- **Актор** — внешняя роль. Сама LifeIsGame актором не является.
- **Ведущий актор** получает полезный результат; второстепенный актор предоставляет внешний сервис.
- Неавторизованный и авторизованный пользователь — разные роли одного человека в разных состояниях доступа.
- Службы Face ID, медиатеки, календаря, уведомлений и Live Activities находятся за границей LifeIsGame.
- Проверки полей, сохранение, сортировка, вычисления и обновление прогресса — шаги сценариев, а не отдельные овалы.
- `include` используется только там, где создание задачи обязательно вызывает общий сложный сценарий планирования.
- UML-связь `extend` не используется: Фаулер рекомендует не усложнять ею модель; условные ветви перечислены как расширения текста.
- Авторизация — предусловие защищённых вариантов использования, поэтому она не включается во все остальные сценарии.

## Сквозное функциональное правило

После авторизации пользователь переходит между пятью разделами через TabBar: «Календарь», «Дневник», «Анализ дня», «Статистика» и «Профиль». Навигация является интерфейсным правилом, а не самостоятельной целью, поэтому отдельного use case для TabBar нет.

## Каталог акторов

| Актор | Тип | Ответственность |
|---|---|---|
| Неавторизованный пользователь | ведущий | Регистрация и вход |
| Авторизованный пользователь | ведущий | Работа с личными данными, задачами, дневником, анализом и достижениями |
| Служба Face ID iOS | второстепенный | Выполнение системной биометрической проверки |
| Системный сервис выбора изображений iOS | второстепенный | Предоставление выбранного изображения аватара |
| Системный календарь iOS | второстепенный | Предоставление внешних событий и занятых интервалов |
| Служба уведомлений iOS | второстепенный | Разрешение и доставка локальных уведомлений |
| Служба Live Activities iOS | второстепенный | Внешнее отображение активной фокус-сессии и передача действия завершения |


## 1. Учётная запись и профиль

### UC01. Зарегистрироваться

- **Уровень:** уровень моря.
- **Ведущий актор:** Неавторизованный пользователь.
- **Второстепенные акторы:** нет.
- **Предусловие:** Пользователь не авторизован.
- **Триггер:** Пользователь выбирает создание учётной записи.

**Главный успешный сценарий**

1. Неавторизованный пользователь запрашивает регистрацию.
2. Система запрашивает имя, дату рождения, электронную почту и пароль.
3. Неавторизованный пользователь передаёт регистрационные данные.
4. Система проверяет обязательные поля, формат и уникальность почты, а также длину пароля.
5. Система создаёт учётную запись и пользовательскую сессию.
6. Система открывает основную часть приложения.

**Расширения сценария**

- 4а. Поле пустое, почта имеет неверный формат или пароль короче шести символов — система показывает ошибки и возвращает к вводу.
- 4б. Почта уже зарегистрирована — система не создаёт дубликат и предлагает выполнить вход.

**Успешная гарантия:** Создана уникальная учётная запись; активная сессия привязана к ней.

### UC02. Войти по электронной почте и паролю

- **Уровень:** уровень моря.
- **Ведущий актор:** Неавторизованный пользователь.
- **Второстепенные акторы:** нет.
- **Предусловие:** Учётная запись существует; пользователь не авторизован.
- **Триггер:** Пользователь выбирает вход по учётным данным.

**Главный успешный сценарий**

1. Неавторизованный пользователь передаёт электронную почту и пароль.
2. Система проверяет соответствие учётных данных.
3. Система создаёт и сохраняет пользовательскую сессию.
4. Система открывает основную часть приложения.

**Расширения сценария**

- 2а. Данные неверны — система сообщает об ошибке и разрешает повторный ввод.

**Успешная гарантия:** После успешного входа сессия восстанавливается при следующих запусках до выхода пользователя.

### UC03. Войти через Face ID

- **Уровень:** уровень моря.
- **Ведущий актор:** Неавторизованный пользователь.
- **Второстепенные акторы:** Служба Face ID iOS.
- **Предусловие:** Face ID поддерживается устройством, настроен в iOS и ранее разрешён для этой учётной записи.
- **Триггер:** Пользователь выбирает вход через Face ID.

**Главный успешный сценарий**

1. Система запрашивает биометрическую проверку у службы Face ID iOS.
2. Пользователь проходит распознавание лица.
3. Служба Face ID подтверждает личность.
4. Система восстанавливает пользовательскую сессию и открывает приложение.

**Расширения сценария**

- 1а. Face ID недоступен — система предлагает вход по электронной почте и паролю.
- 3а. Распознавание неуспешно или отменено — система не открывает учётную запись и предлагает обычный вход.

**Успешная гарантия:** Доступ предоставлен только после успешной системной биометрической проверки.

### UC04. Просмотреть профиль

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** нет.
- **Предусловие:** Пользователь авторизован.
- **Триггер:** Пользователь открывает раздел «Профиль».

**Главный успешный сценарий**

1. Система получает данные текущей учётной записи.
2. Система показывает имя, почту, скрытое представление пароля, аватар, уровень и накопленный опыт.
3. Система показывает настройки уведомлений и, на поддерживаемом устройстве, Face ID.

**Расширения сценария**

- 3а. Устройство не поддерживает Face ID — настройка Face ID не отображается.

**Успешная гарантия:** Пользователь видит актуальные данные только своей учётной записи.

### UC05. Изменить аватар

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** Системный сервис выбора изображений iOS.
- **Предусловие:** Пользователь авторизован и открыл профиль.
- **Триггер:** Пользователь выбирает изменение аватара.

**Главный успешный сценарий**

1. Система открывает системный выбор изображения.
2. Пользователь выбирает изображение в медиатеке iOS.
3. Системный сервис выбора изображений iOS передаёт выбранное изображение приложению.
4. Система сохраняет и показывает новый аватар.

**Расширения сценария**

- 2а. Пользователь отменяет выбор — аватар не изменяется.
- 2б. Доступ к медиатеке отсутствует — система сообщает, как изменить разрешение iOS.

**Успешная гарантия:** Новый аватар привязан к текущему пользователю; другие данные профиля не изменены.

### UC06. Настроить вход через Face ID

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** Служба Face ID iOS.
- **Предусловие:** Пользователь авторизован; устройство поддерживает Face ID.
- **Триггер:** Пользователь изменяет настройку Face ID в профиле.

**Главный успешный сценарий**

1. Пользователь включает или выключает вход через Face ID.
2. При включении система проверяет доступность биометрии через службу Face ID iOS.
3. Система сохраняет новое состояние настройки для текущей учётной записи.

**Расширения сценария**

- 2а. Биометрия не настроена или недоступна — система не включает вход и показывает причину.

**Успешная гарантия:** Настройка действует только для текущей учётной записи и поддерживаемого устройства.

### UC07. Выйти из учётной записи

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** нет.
- **Предусловие:** Пользователь авторизован.
- **Триггер:** Пользователь выбирает выход.

**Главный успешный сценарий**

1. Система запрашивает подтверждение.
2. Пользователь подтверждает выход.
3. Система завершает сохранённую сессию.
4. Система показывает экран авторизации.

**Расширения сценария**

- 2а. Пользователь отменяет действие — текущая сессия сохраняется.

**Успешная гарантия:** После подтверждения защищённые разделы недоступны без новой авторизации.


## 2. Календарь и планирование

### UC08. Просмотреть план выбранного дня

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** Системный календарь iOS.
- **Предусловие:** Пользователь авторизован.
- **Триггер:** Пользователь открывает календарь или выбирает дату.

**Главный успешный сценарий**

1. Пользователь выбирает календарный день.
2. Система получает собственные задачи и события этого дня.
3. При наличии разрешения система получает события системного календаря iOS.
4. Система объединяет элементы и сортирует их по времени начала.
5. Система рассчитывает число выполненных задач и подзадач и общее число запланированных дел.
6. Система показывает план дня и его прогресс; события iOS помечаются как доступные только для просмотра.

**Расширения сценария**

- 3а. Доступ к календарю не предоставлен — система показывает только внутренние элементы и предлагает подключение.
- 4а. События изменились или приложение вернулось в активное состояние — система повторно загружает и обновляет список.

**Успешная гарантия:** Показан актуальный план выбранного дня без изменения системных событий.

### UC09. Отфильтровать элементы календаря

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** нет.
- **Предусловие:** Открыт календарь выбранного дня.
- **Триггер:** Пользователь выбирает фильтр «Все», «Выполняемые» или «Завершённые».

**Главный успешный сценарий**

1. Пользователь выбирает состояние элементов.
2. Система применяет фильтр к задачам и подзадачам сложных задач.
3. Для события состояние определяется относительно его временного интервала; пользователь не меняет его вручную.
4. Система показывает отфильтрованный список, сохраняя сортировку по времени.

**Расширения сценария**

- 4а. Подходящих элементов нет — система показывает пустой результат без изменения исходного плана.

**Успешная гарантия:** Фильтрация не изменяет данные и не запускает повторное планирование.

### UC10. Подключить системный календарь

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** Системный календарь iOS.
- **Предусловие:** Пользователь авторизован; доступ ещё не предоставлен или был отозван.
- **Триггер:** Пользователь явно соглашается подключить календарь iOS.

**Главный успешный сценарий**

1. Система объясняет назначение доступа.
2. Пользователь подтверждает запрос.
3. Система вызывает системный запрос разрешения.
4. Пользователь предоставляет доступ в iOS.
5. Система загружает события и обновляет календарь приложения.

**Расширения сценария**

- 4а. Пользователь отказывает — приложение продолжает работать только с внутренними задачами и событиями.

**Успешная гарантия:** Доступ запрашивается только после явного действия пользователя; импортированные события не редактируются.

### UC11. Создать событие с фиксированным временем

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** нет.
- **Предусловие:** Пользователь авторизован.
- **Триггер:** Пользователь выбирает создание события.

**Главный успешный сценарий**

1. Пользователь задаёт название, важность, сложность, точные начало и окончание; описание указывает при необходимости.
2. Система проверяет обязательное название, порядок времени и минимальную длительность 15 минут.
3. Система сохраняет событие без автоматического переноса.
4. Система отображает название, начало и окончание в календаре и учитывает интервал как занятый.

**Расширения сценария**

- 2а. Данные некорректны — система не сохраняет событие и показывает, что нужно исправить.

**Успешная гарантия:** Событие занимает точно выбранный интервал и участвует в последующем планировании.

### UC12. Создать обычную задачу

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** Системный календарь iOS — через UC15.
- **Предусловие:** Пользователь авторизован.
- **Триггер:** Пользователь выбирает создание обычной задачи.

**Главный успешный сценарий**

1. Пользователь задаёт название, важность, сложность, период выполнения и предполагаемую продолжительность; описание указывает при необходимости.
2. Система проверяет обязательные и временные данные, включая минимальный блок 15 минут.
3. Система включает UC15 «Автоматически сформировать план».
4. Система сохраняет задачу и показывает выбранный интервал в календаре.

**Расширения сценария**

- 2а. Данные некорректны — задача не сохраняется; пользователь исправляет поля.

**Успешная гарантия:** Созданная задача имеет непересекающийся плановый интервал и привязана к текущему пользователю.

### UC13. Создать сложную задачу

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** Системный календарь iOS — через UC15.
- **Предусловие:** Пользователь авторизован.
- **Триггер:** Пользователь выбирает создание сложной задачи.

**Главный успешный сценарий**

1. Пользователь задаёт общие данные сложной задачи и общий период выполнения.
2. Пользователь добавляет как минимум одну подзадачу.
3. Для каждой подзадачи пользователь задаёт название, важность, сложность и продолжительность; описание необязательно.
4. До сохранения пользователь при необходимости изменяет состав и данные подзадач.
5. Система проверяет обязательные данные и минимальную длительность блоков.
6. Система включает UC15 «Автоматически сформировать план» для распределения подзадач.
7. Система сохраняет сложную задачу и итоговый план.

**Расширения сценария**

- 2а. Подзадач нет — система не позволяет сохранить сложную задачу.
- 5а. Данные подзадачи некорректны — система указывает проблемную подзадачу и возвращает к редактированию.

**Успешная гарантия:** Сложная задача содержит хотя бы одну подзадачу; подзадачи распределены без пересечений.

### UC14. Управлять собственной задачей

- **Уровень:** уровень моря.
- **Ведущий актор:** Авторизованный пользователь.
- **Второстепенные акторы:** нет.
- **Предусловие:** Собственная задача или подзадача существует.
- **Триггер:** Пользователь открывает действие над собственной задачей.

**Главный успешный сценарий**

1. Пользователь выбирает собственную задачу или подзадачу.
2. Система показывает доступные действия.
3. Пользователь изменяет название, описание, важность или сложность либо отмечает выполнение/удаляет элемент.
4. Система проверяет и сохраняет изменение.
5. Система пересчитывает прогресс дня, статистику и прогресс достижений; связанные напоминания обновляются или отменяются.

**Расширения сценария**

- 3а. Пользователь отменяет изменение — данные остаются прежними.
- 3б. Выбрано импортированное событие iOS — система разрешает только просмотр и не показывает команды редактирования.

**Успешная гарантия:** Изменена только выбранная собственная задача; производные показатели согласованы с новым состоянием.

### UC15. Автоматически сформировать план

- **Уровень:** уровень рыб.
- **Ведущий актор:** включается UC12 или UC13.
- **Второстепенные акторы:** Системный календарь iOS.
- **Предусловие:** Данные задачи проверены; известен период и требуемая продолжительность.
- **Триггер:** UC12 или UC13 переходит к обязательному планированию.

**Главный успешный сценарий**

1. Система получает занятые интервалы собственных задач, событий приложения и доступных событий iOS.
2. Система строит свободные интервалы преимущественно в пределах 08:00–23:00.
3. Система учитывает длительность, важность и сложность; важные и сложные элементы по возможности размещает раньше.
4. Для обычной задачи система выбирает подходящий свободный интервал; для сложной — распределяет все подзадачи в общем периоде.
5. Система проверяет отсутствие пересечений и формирует итоговый план.

**Расширения сценария**

- 1а. Доступ к календарю iOS отсутствует — план строится по внутренним данным, а ограничение источников сообщается пользователю.
- 4а. В указанном периоде нет подходящего интервала — система выбирает ближайшее доступное время.

## Почему некоторые требования не стали отдельными овалами

- Проверка уникальности почты — шаг UC01.
- Сохранение и восстановление сессии — гарантия UC01–UC03.
- Сортировка и расчёт прогресса дня — шаги UC08.
- Добавление и редактирование подзадач до сохранения — шаги UC13.
- Разделение задачи после 23:00 — условная ветвь UC15.
- Расчёт длительности сна — шаг UC20.
- Обновление статистики и достижений — постусловие сценариев, изменяющих данные.
- Отображение данных на конкретном экране само по себе не образует связь include или extend.
