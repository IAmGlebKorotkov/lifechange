# Аудит требований и UML-модели Luma

## 1. Границы аудита и правила чтения

Аудит выполнен только по трём предоставленным источникам: `requirements.md`, `coursework-corrected.md` и десяти PNG-файлам из каталога `uml`. Код приложения, результаты тестовых прогонов и исходники диаграмм в объём проверки не входили. Поэтому названия программных компонентов ниже означают только заявленное в тексте место реализации, а не подтверждение фактического выполнения требования.

При расхождении источников приоритет имеет техническое задание из `requirements.md`. Диаграмма вариантов использования показывает цели и взаимодействия акторов, но не заменяет точные условия, поля, интервалы, формулы и альтернативы текстового требования. Все новые и исправленные материалы должны использовать только название **Luma**.

Текущий текст объединяет требования в группы `FR-01`–`FR-14`. Для устойчивой трассировки внутри группы введён атомарный идентификатор вида `FR-03.04`; рядом сохранён исходный номер абзаца технического задания. Идентификатор группы не считается заменой атомарным требованиям.

## 2. Нормализованный список функциональных требований

### FR-01. Регистрация, вход и сессия

- `FR-01.01` (`P0003`) — при регистрации пользователь указывает имя, дату рождения, адрес электронной почты и пароль.
- `FR-01.02` (`P0004`) — поля регистрации не остаются пустыми; пароль содержит не менее шести символов.
- `FR-01.03` (`P0005`) — для входа пользователь вводит адрес электронной почты и пароль.
- `FR-01.04` (`P0006`) — после успешного входа Luma сохраняет пользовательскую сессию, чтобы не требовать учётные данные при каждом запуске.

### FR-02. Face ID, профиль и выход

- `FR-02.01` (`P0007`) — пользователь может включить вход с распознаванием лица.
- `FR-02.02` (`P0008`) — если Face ID недоступен или проверка неуспешна, пользователь может войти по электронной почте и паролю.
- `FR-02.03` (`P0009`) — пользователь может завершить текущую сессию и вернуться на экран входа.
- `FR-02.04` (`P0143`) — профиль отображает имя, адрес электронной почты, скрытое представление пароля, аватар, текущий уровень и накопленный опыт.
- `FR-02.05` (`P0144`) — пользователь может выбрать изображение профиля из медиатеки устройства.
- `FR-02.06` (`P0145`) — в профиле размещены настройки Face ID и уведомлений.
- `FR-02.07` (`P0146`) — настройка Face ID отображается только на поддерживающих технологию устройствах.
- `FR-02.08` (`P0147`) — выход из учётной записи выполняется после подтверждения пользователя.

Примечание: формулировка «просмотр и изменение профиля» из таблицы 1.2 шире технического задания. Техническое задание явно разрешает менять аватар и настройки, но не задаёт изменение имени, электронной почты или пароля.

### FR-03. Навигация, календарь и управление собственными задачами

- `FR-03.01` (`P0011`) — постоянная нижняя панель `TabBar` содержит пять разделов: «Календарь», «Дневник», «Анализ дня», «Статистика» и «Профиль».
- `FR-03.02` (`P0013`) — пользователь выбирает дату и просматривает запланированные на неё задачи и события.
- `FR-03.03` (`P0014`) — для выбранного дня отображаются количество выполненных элементов и общее количество запланированных дел.
- `FR-03.04` (`P0015`) — задачи и события сортируются по времени начала.
- `FR-03.05` (`P0016`) — пользователь фильтрует элементы по состояниям «Все», «Выполняемые» и «Завершённые».
- `FR-03.06` (`P0017`) — для сложной задачи фильтр применяется к её подзадачам.
- `FR-03.07` (`P0018`) — выполненные задачи и подзадачи учитываются в общем прогрессе дня.
- `FR-03.08` (`P0022`) — для собственной задачи пользователь может изменить название, описание, важность и сложность, отметить её выполненной и удалить.

### FR-04. Интеграция с системным календарём iOS

- `FR-04.01` (`P0019`) — календарь совместно отображает собственные задачи Luma и события системного календаря iOS.
- `FR-04.02` (`P0020`) — доступ к системному календарю запрашивается только с разрешения пользователя.
- `FR-04.03` (`P0021`) — список автоматически обновляется при изменении системных событий или возвращении Luma в активное состояние.

### FR-05. Создание элементов календаря

- `FR-05.01` (`P0025`) — пользователь может создать обычную задачу, сложную задачу или событие с фиксированным временем.
- `FR-05.02` (`P0026`) — для каждого элемента пользователь указывает название, важность и сложность.
- `FR-05.03` (`P0027`) — для события пользователь указывает точное время начала и окончания.
- `FR-05.04` (`P0028`) — для задачи пользователь указывает период выполнения в виде дат и предполагаемую продолжительность.
- `FR-05.05` (`P0029`) — элемент без названия не сохраняется.
- `FR-05.06` (`P0030`) — окончание события не предшествует его началу.
- `FR-05.07` (`P0031`) — минимальная продолжительность одного планируемого блока составляет 15 минут.
- `FR-05.08` (`P0034`) — событие сохраняется на выбранное время без автоматического переноса.
- `FR-05.09` (`P0035`) — календарь показывает название события, время начала и окончания.
- `FR-05.10` (`P0036`) — событие считается занятым интервалом при планировании других задач.

### FR-06. Автоматическое планирование обычной задачи

- `FR-06.01` (`P0039`) — пользователь задаёт период, в пределах которого обычная задача должна быть выполнена.
- `FR-06.02` (`P0040`) — после создания обычной задачи Luma автоматически выбирает подходящий свободный интервал.
- `FR-06.03` (`P0041`) — планирование учитывает существующие задачи и события системного календаря.
- `FR-06.04` (`P0042`) — новая задача не пересекается с занятыми интервалами.
- `FR-06.05` (`P0043`) — выбор времени учитывает важность, сложность и предполагаемую продолжительность задачи.
- `FR-06.06` (`P0044`) — важные и сложные задачи по возможности размещаются в более ранних интервалах.
- `FR-06.07` (`P0045`) — если в заданном периоде нет подходящего интервала, выбирается ближайшее доступное время.

### FR-07. Создание и планирование сложной задачи

- `FR-07.01` (`P0048`) — пользователь может разделить сложную задачу на подзадачи.
- `FR-07.02` (`P0049`) — сложная задача содержит не менее одной подзадачи.
- `FR-07.03` (`P0050`) — для каждой подзадачи задаются название, важность, сложность и предполагаемая продолжительность.
- `FR-07.04` (`P0051`) — описание подзадачи необязательно.
- `FR-07.05` (`P0052`) — до сохранения сложной задачи пользователь может добавлять и изменять подзадачи.
- `FR-07.06` (`P0053`) — Luma автоматически распределяет подзадачи внутри общего периода сложной задачи.
- `FR-07.07` (`P0054`) — распределение учитывает занятые интервалы, важность, сложность и продолжительность каждой подзадачи.
- `FR-07.08` (`P0055`) — подзадачи не пересекаются друг с другом и с ранее запланированными элементами.
- `FR-07.09` (`P0056`) — после распределения формируется итоговый план сложной задачи.

### FR-08. Ограничение дня и разделение задачи

- `FR-08.01` (`P0059`) — задачи преимущественно планируются в интервале 08:00–23:00.
- `FR-08.02` (`P0060`) — если задача выходит за границу дня, Luma предлагает разделить её.
- `FR-08.03` (`P0061`) — только после согласия пользователя остаток переносится на следующий день.
- `FR-08.04` (`P0062`) — перенесённая часть отображается как продолжение исходной задачи.

### FR-09. Уведомления

- `FR-09.01` (`P0064`) — пользователь включает и выключает уведомления в настройках профиля.
- `FR-09.02` (`P0065`) — при первом включении Luma запрашивает системное разрешение на уведомления.
- `FR-09.03` (`P0066`) — если уведомления включены в Luma, но запрещены в iOS, приложение сообщает о необходимости изменить системные настройки.
- `FR-09.04` (`P0067`) — для запланированной задачи создаются уведомления за 30 и за 5 минут до начала.
- `FR-09.05` (`P0068`) — для сложной задачи уведомления создаются отдельно по каждой подзадаче.
- `FR-09.06` (`P0069`) — напоминания о дневнике сна отправляются в 08:00 и 12:00, если запись ещё не заполнена.
- `FR-09.07` (`P0070`) — напоминания о дневнике эмоций отправляются в 18:00 и 20:00.
- `FR-09.08` (`P0071`) — после заполнения соответствующего дневника оставшиеся напоминания этого дня отменяются.
- `FR-09.09` (`P0072`) — пользователь может открыть отдельный экран доставленных уведомлений.
- `FR-09.10` (`P0073`) — доставленные уведомления отображаются в обратном хронологическом порядке.
- `FR-09.11` (`P0074`) — при отключении уведомлений отменяются все запланированные Luma напоминания.

### FR-10. Дневник эмоций и сна

- `FR-10.01` (`P0076`) — дневник содержит записи двух видов: эмоциональное состояние и сведения о сне.
- `FR-10.02` (`P0077`) — каждая запись связана с текущим пользователем и днём.
- `FR-10.03` (`P0078`) — записи используются при построении статистики и анализе состояния.
- `FR-10.04` (`P0080`) — пользователь выбирает эмоцию из перечня: радость, грусть, злость, тревога, покой и любовь.
- `FR-10.05` (`P0081`) — для каждой выбранной эмоции задаётся интенсивность по десятибалльной шкале.
- `FR-10.06` (`P0082`) — пользователь может добавить текстовую причину эмоционального состояния.
- `FR-10.07` (`P0083`) — описание причины необязательно.
- `FR-10.08` (`P0084`) — сохранение записи эмоций отменяет оставшиеся напоминания об эмоциях на текущий день.
- `FR-10.09` (`P0087`) — пользователь указывает время отхода ко сну и пробуждения.
- `FR-10.10` (`P0088`) — Luma автоматически рассчитывает продолжительность сна по введённым значениям.
- `FR-10.11` (`P0089`) — сохранение записи сна отменяет оставшиеся напоминания о сне на текущий день.

### FR-11. Фокус-сессия и Live Activity

- `FR-11.01` (`P0091`) — пользователь выбирает незавершённую задачу или подзадачу текущего дня.
- `FR-11.02` (`P0092`) — длительность фокус-сессии равна предполагаемой продолжительности выбранной задачи.
- `FR-11.03` (`P0093`) — до запуска пользователь выбирает плейлист или режим без музыки.
- `FR-11.04` (`P0094`) — после запуска начинается обратный отсчёт оставшегося времени.
- `FR-11.05` (`P0095`) — во время сессии воспроизводится музыка выбранного плейлиста.
- `FR-11.06` (`P0096`) — после окончания сессии музыка останавливается.
- `FR-11.07` (`P0097`) — длительность сессии сохраняется для статистики и прогресса достижений.
- `FR-11.08` (`P0098`) — после завершения сессии выбранная задача отмечается выполненной.
- `FR-11.09` (`P0100`) — во время фокус-сессии Luma создаёт Live Activity.
- `FR-11.10` (`P0101`) — на поддерживаемых устройствах Live Activity отображается на экране блокировки и в Dynamic Island.
- `FR-11.11` (`P0102`) — Live Activity показывает название и тип задачи, а также оставшееся время.
- `FR-11.12` (`P0103`) — пользователь может завершить задачу непосредственно из Live Activity.
- `FR-11.13` (`P0104`) — после окончания или принудительного завершения сессии Live Activity закрывается.

### FR-12. Анализ состояния пользователя

- `FR-12.01` (`P0106`) — анализ строится на задачах, записях сна и эмоционального дневника.
- `FR-12.02` (`P0107`) — расчёт учитывает длительность сна, эмоции, число выполненных и оставшихся задач, их важность, сложность и предполагаемую продолжительность.
- `FR-12.03` (`P0108`) — события системного календаря учитываются при определении занятого и доступного времени.
- `FR-12.04` (`P0109`) — анализ учитывает просроченные задачи и нагрузку следующего дня.
- `FR-12.05` (`P0110`) — результат содержит оценки ресурса, нагрузки и баланса по шкале 0–100.
- `FR-12.06` (`P0111`) — определяется уровень нагрузки: низкий, сбалансированный, высокий или перегрузка.
- `FR-12.07` (`P0112`) — отображается степень точности анализа, зависящая от количества доступных данных.
- `FR-12.08` (`P0113`) — при недостатке записей результат помечается как предварительный.
- `FR-12.09` (`P0114`) — формируется краткое описание состояния пользователя.
- `FR-12.10` (`P0115`) — формируется не более четырёх персональных рекомендаций.
- `FR-12.11` (`P0116`) — рекомендации могут быть связаны с недостатком сна, высокой нагрузкой, просроченными задачами, эмоциональным напряжением или необходимостью переноса части дел.

### FR-13. Общая и подробная статистика

- `FR-13.01` (`P0118`) — общий экран показывает показатели за последние семь дней.
- `FR-13.02` (`P0119`) — статистика содержит число выполненных и общее число запланированных задач.
- `FR-13.03` (`P0120`) — отображаются показатели качества сна, эффективности выполнения задач и эмоционального состояния.
- `FR-13.04` (`P0121`) — эффективность учитывает продолжительность, важность и сложность выполненных задач.
- `FR-13.05` (`P0123`) — подробная статистика разделена на категории «Эмоции», «Сон» и «Задачи».
- `FR-13.06` (`P0124`) — статистика эмоций показывает преобладающую эмоцию за 30 дней, распределение записей и среднюю интенсивность.
- `FR-13.07` (`P0125`) — статистика эмоций показывает динамику за семь дней и историю последних записей.
- `FR-13.08` (`P0126`) — статистика сна показывает дату, время засыпания, время пробуждения и продолжительность сна.
- `FR-13.09` (`P0127`) — статистика задач охватывает последние 30 дней.
- `FR-13.10` (`P0128`) — для каждого дня показываются выполненные и все запланированные задачи.
- `FR-13.11` (`P0129`) — пользователь может открыть выбранный день и увидеть состав выполненных и невыполненных задач.

### FR-14. Достижения, опыт и уровни

- `FR-14.01` (`P0131`) — Luma содержит систему достижений для дополнительной мотивации.
- `FR-14.02` (`P0132`) — условия достижений связаны с задачами, дневниками сна и эмоций, продолжительностью сна и фокус-сессиями.
- `FR-14.03` (`P0133`) — для достижения отображаются название, описание цели, текущее и требуемое значения.
- `FR-14.04` (`P0134`) — достижение имеет одно из состояний: заблокировано, разблокировано или открыто.
- `FR-14.05` (`P0135`) — после выполнения условия пользователь может открыть достижение и получить опыт.
- `FR-14.06` (`P0136`) — прогресс автоматически обновляется при изменении задач, дневников и длительности фокус-сессий.
- `FR-14.07` (`P0138`) — за каждое открытое достижение начисляется 50 единиц опыта.
- `FR-14.08` (`P0139`) — после накопления 250 единиц опыта пользователь переходит на следующий уровень.
- `FR-14.09` (`P0140`) — каждому уровню соответствует звание.
- `FR-14.10` (`P0141`) — уровень, звание и прогресс до следующего уровня отображаются на экране достижений и в профиле.

## 3. Нефункциональные требования: критерии и пробелы

| ID и источник | Нормализованное требование | Метрика или наблюдаемое условие | Условие проверки | Метод проверки | Пробел в ТЗ или доказательствах |

### Существенные расхождения текущего текста и ТЗ

1. Таблица 1.2 расширяет `FR-02` до произвольного «изменения профиля», хотя ТЗ разрешает только выбор аватара и изменение настроек Face ID/уведомлений.
2. `P0286` вводит эмоцию «страх», которой нет в заданном перечне, и не подтверждает обработку эмоции «любовь».
3. `P0279`, `P0284`, `P0289` и `P0290` вводят возраст пользователя, возрастные диапазоны сна, базовое значение 86, веса и нижнюю границу результата 10. Это допустимо только как явно обозначенные проектные решения. Они не должны приписываться заказчику; нижняя граница 10 не доказывает требуемую шкалу 0–100.
4. В `FR-09` описано запасное уведомление «через несколько секунд», если точка за пять минут уже прошла. Такое поведение отсутствует в ТЗ и должно быть либо согласовано как правило, либо отмечено отклонением.
5. Укрупнённая таблица 3.1 не доказывает атомарные требования: особенно слабо подтверждены ближайший доступный интервал, раннее размещение важных/сложных задач, обновление календаря после внешнего изменения, точность/баланс анализа, точные поля статистики, команда завершения из Live Activity и скрытый пароль в профиле.
6. В материалах заказчик обозначен абстрактно. Нет фактов о его наименовании/роли, способе получения требований и документированной приёмке. ## 5. Аудит десяти UML-диаграмм

### Общие замечания ко всему комплекту

Все десять файлов просмотрены визуально как RGBA-изображения и дополнительно на временной белой подложке. Угловая прозрачность не является чёрным фоном. После размещения на белой странице основной текст читается, однако серо-синие линии заметно тоньше и светлее чёрных контуров овалов. Для печати следует использовать непрозрачный белый фон либо гарантировать белую подложку в документе, чёрные или одинаково тёмные линии и текст, а также проверить итоговый PDF в фактическом масштабе страницы.

Обязательная общая правка: добавить прямоугольник границы системы с подписью **Luma**; все варианты использования разместить внутри него, а акторов — снаружи. Заголовок рисунка не является границей системы. Ассоциации актор–вариант использования показывать сплошными линиями без стрелок. `«include»` и `«extend»` показывать пунктиром с открытым наконечником у включаемого или базового прецедента соответственно. Не использовать эти отношения для обозначения последовательности шагов.

Крупные жёлтые заметки на диаграммах 01, 02, 03, 06, 08 и 09 занимают значимую часть листа и дублируют поясняющий текст. Их лучше перенести в абзац перед/после рисунка. Если заметка остаётся, она не должна подменять сценарий и не должна быть единственным местом, где объяснена роль актора. Цвет голов акторов также не должен быть единственным способом различить ведущую и поддерживающую роль.

## 6. Сценарии, которые необходимо описать текстом

Для каждого сценария достаточно указать ID, цель, основного актора, предусловия, триггер, основной поток, альтернативы/ошибки и результат. Следующие сценарии нельзя оставлять только в виде овалов:

1. `UC-01 Регистрация` — четыре поля, пустые значения, пароль короче шести символов, успешное создание записи.
2. `UC-02 Вход и восстановление сессии` — вход по электронной почте/паролю, неверные данные, сохранённая сессия и повторный запуск.
3. `UC-03 Вход через Face ID` — поддержка устройства, включённая настройка, успешная проверка, отказ/ошибка и резервный вход по паролю.
4. `UC-04 Работа с профилем и выход` — состав отображаемых данных, выбор изображения с разрешением/отказом, настройка Face ID и уведомлений, подтверждение выхода.
5. `UC-05 Просмотр плана дня` — выбор даты, совместный список, сортировка, прогресс, отсутствие данных, разрешение календаря, изменение внешнего события и возврат приложения в active.
6. `UC-06 Фильтрация и управление собственной задачей` — три фильтра с подзадачами; изменение полей, завершение и удаление; внешнее событие остаётся read-only.
7. `UC-07 Создание события` — обязательные поля, времена, минимальный блок 15 минут, запрет окончания раньше начала, сохранение без переноса и учёт как занятого интервала.
8. `UC-08 Создание и планирование обычной задачи` — период, длительность, занятые интервалы, факторы приоритета, отсутствие окна в периоде и выбор ближайшего времени.
9. `UC-09 Создание и планирование сложной задачи` — минимум одна подзадача, добавление/изменение до сохранения, необязательное описание, распределение без пересечений и итоговый план.
10. `UC-10 Разделение задачи после 23:00` — обнаружение границы, отказ без изменения, согласие, перенос остатка на следующий день и отображение продолжения.
11. `UC-11 Настройка уведомлений` — первое разрешение, системный отказ при включённой настройке, отключение и отмена всех планов.
12. `UC-12 Планирование и получение напоминаний` — 30/5 минут, отдельные подзадачи, расписания сна/эмоций, отмена после записи и поведение при уже прошедшем времени.
13. `UC-13 Просмотр истории уведомлений` — только доставленные уведомления, отдельный экран, обратный хронологический порядок.
14. `UC-14 Запись эмоций` — точный перечень, интенсивность 1–10, необязательная причина, пользователь/день, сохранение и отмена напоминаний.
15. `UC-15 Запись сна` — время сна и пробуждения, правило расчёта длительности, пользователь/день, сохранение и отмена напоминаний. Переход через полночь следует закрепить как согласованное правило, поскольку в ТЗ он прямо не сформулирован.
16. `UC-16 Фокус-сессия` — выбор незавершённого элемента текущего дня, длительность, плейлист/тишина, обратный отсчёт, остановка музыки, сохранение длительности и завершение задачи.
17. `UC-17 Live Activity` — условие поддержки, экран блокировки/Dynamic Island, состав данных, завершение из Live Activity, принудительное завершение и закрытие активности.
18. `UC-18 Анализ дня` — полный набор входов, три оценки 0–100, категория, точность, предварительный результат, краткое описание и максимум четыре рекомендации.
19. `UC-19 Просмотр статистики` — сводка 7 дней; категории и их точные поля/периоды; расчёт эффективности; переход к составу выбранного дня.
